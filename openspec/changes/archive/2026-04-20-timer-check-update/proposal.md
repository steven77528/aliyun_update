# Proposal: 定时检查公网 IP 并更新阿里云安全组（扩展版）

## Why
- 家庭宽带或云主机公网 IP 可能变化，导致基于白名单的访问中断。
- 需要一个最小可运行方案，自动完成“检测变化并更新安全组规则”的闭环，减少人工维护。

## Scope (Current Release)
本期覆盖能力：

1. **定时检查公网 IP**
   - 支持可配置检查间隔（例如每小时）。
2. **变化检测与条件更新**
   - 将本次 IP 与上次记录值比较；仅在发生变化时调用更新逻辑。
3. **阿里云安全组规则更新（多目标）**
   - 支持单账号下多个安全组/规则更新。
   - 支持多个账号分别更新与隔离执行。
4. **最小可观测性**
   - 记录每次检查结果：当前 IP、是否变化、是否触发更新、更新结果、错误摘要。
5. **监控与报警**
   - 当检查或更新失败时，通过至少一种通道（Webhook）发送告警。
   - 支持告警限频，避免告警风暴。
6. **基础可靠性与安全**
   - 基础错误捕获与有限重试（IP 获取、API 调用）。
   - 凭证通过环境变量或外部注入，避免日志/明文配置泄露。
7. **执行模式**
   - 支持单次执行模式。
   - 支持内置定时循环执行模式（不依赖外部 cron）。

## Non-goals (Out of Scope for Current Release)
- 复杂调度编排平台集成（如工作流引擎）。
- 多告警渠道全覆盖（邮件/IM 等），本期至少实现 Webhook。
- 完整生产级发布流水线（CI/CD 模板与发布治理）。

## Success Criteria
满足以下条件即视为本期达成：

1. 在连续多次检查中，IP 未变化时**不会**调用安全组更新 API。
2. IP 发生变化后，在一次调度周期内成功更新目标规则，并记录成功日志。
3. 当 IP 获取失败或阿里云 API 调用失败时，能记录可诊断错误信息，不泄露密钥。
4. 通过配置可调整检查间隔与目标规则参数，无需改代码。
5. 支持单次执行与内置定时执行两种模式。
6. 支持至少一个账号下多个安全组规则更新，并输出逐项结果。
7. 支持多个账号配置，单账号失败不影响其他账号执行。
8. 失败场景可触发 Webhook 告警，并具备限频策略。

## Risks / Open Questions
- 公网 IP 获取来源的可用性与准确性（MVP 建议采用多源查询 + 一致性判定；单源失败可回退）。
- 阿里云 API 限流与重试退避策略阈值。
- “规则标识”定位方式（按规则 ID 还是按端口/协议匹配）在不同账户中的一致性。

## Risk #1 Mitigation Direction
- 使用多个公网 IP 源进行查询（例如主源 + 备源）。
- 对多源结果做一致性判定：
  - 多数一致：采用多数结果；
  - 全部不一致：本轮不更新安全组，仅记录告警级日志，等待下轮重试。
- 任一单源不可用时不中断流程，继续使用其他可用源，提升可用性。
